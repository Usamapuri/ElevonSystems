## What Phase 1 delivered

- **Login throttle**: `internal/ratelimit`, a sliding-window limiter with a bounded sweep (10 000 keys). Login enforces 10 failures / 15 min per identifier+IP → `429 rate_limited`.
- **Forgot / reset / change password**: `internal/email` wraps Resend (dev mode — `RESEND_API_KEY`/`EMAIL_FROM` unset — logs the reset URL instead of sending). `POST /auth/forgot-password` and `POST /auth/reset-password` are public; `POST /auth/change-password` is staff-only. Password policy is 8–72 bytes everywhere (`weak_password` / `password_too_long`). New env var `APP_URL` builds the reset link. `change-password` answers `400` (not `401`) for a wrong current password, so the client's global 401 interceptor doesn't log the user out.
- **`internal/staffpin`**: admin-only PIN identify, bcrypt-compares every candidate (no username-style lookup, so timing doesn't leak which PIN matched).
- **Users API**: `GET/POST /admin/users`, `PUT /admin/users/:id`, `PUT /admin/users/:id/pin`. Guard codes: `cannot_modify_self`, `last_admin`, `username_taken`, `email_taken`, `pin_in_use`, `pin_not_allowed_for_role`, `invalid_pin_format`. A Postgres advisory lock (`pg_advisory_xact_lock`) serialises PIN writes and role/active changes. Usernames are immutable; users are deactivated, never deleted; demotion clears the PIN.
- **Settings API**: `internal/settings` (21 keys, per-key rules, a `notNull` guard so only `tax_rate_credit` may be null, cross-key printable-width check, `Save` casts `$2::jsonb`). `GET /settings` (staff), `PUT /admin/settings` (admin, all-or-nothing) with codes `unknown_setting` / `invalid_setting_value`. `settings.LoadDayBoundaryHour` runs at boot and again after every save.
- **Settings screen**: tabs for Business, Tax, Receipt, Day close, Credit, and a Users tab (create, edit, deactivate, set-PIN dialogs).
- **Frontend auth surface**: `/forgot-password`, `/reset-password` pages, a login-page link to them, and a `ChangePasswordDialog` in the user menu.
- **Contract tests added**: `handlers/no_raw_error_contract_test.go` (no `err.Error()` reaches a client); the public-route contract test now pins the exact three public lines (`POST /auth/login`, `POST /auth/forgot-password`, `POST /auth/reset-password`).
- **Task 4b**: `testdb.Fresh` takes a session advisory lock so parallel test packages sharing one `TEST_DATABASE_URL` no longer race.

## How to run it here

```bash
cp .env.example .env         # already exists locally with INITIAL_ADMIN_PASSWORD=correct-horse-battery (gitignored)
docker compose -f docker-compose.dev.yml up --build
```
The sibling repo's dev containers (`pos-backend-dev` on 8080, `pos-frontend-dev` on 3000) are usually running on this machine, so the local `.env` overrides the host ports: API `http://localhost:18080`, Vite `http://127.0.0.1:13000`, Postgres `15432`. Use `127.0.0.1`, not `localhost`, in the browser (localhost resolves to IPv6 first here).

Without Docker for the API: `cd backend && DATABASE_URL=... INITIAL_ADMIN_PASSWORD=... GIN_MODE=debug go run .`
Tests: `cd backend && go vet ./... && go test ./...` (set `TEST_DATABASE_URL` to a disposable DB to run the DB-backed tests) · `cd frontend && npm run type-check && npm run test`.

## Deviations and gotchas to carry forward

- **Route guards use `beforeLoad` + `redirect`, never `<Navigate>` in a layout render.** The installed TanStack Router resolved to 1.170 (retail pins 1.57); its `Navigate` re-fires on every render while a redirect is pending and looped on logout. Keep this pattern for every new route.
- `frontend/src/routeTree.gen.ts` is generated by the router plugin during `vite build` / `vite dev`; it is committed so `tsc` works, never hand-edited.
- `debounce` in `lib/utils.ts` was changed to `ReturnType<typeof setTimeout>` (no `@types/node` here).
- Migrations must stay idempotent; `migrations_idempotent_contract_test.go` enforces the accepted forms (`IF NOT EXISTS`, `DROP CONSTRAINT IF EXISTS` before `ADD CONSTRAINT`, `ON CONFLICT` on seeds).
- The isolation grep for the forbidden tenant name legitimately hits `CLAUDE.md` and `.claude/settings.json`, which name what to avoid; anywhere else is a violation.
- JWT `iat` is whole-second, so a token minted in the same second as a revocation is rejected — tests look 2 s back.
- `settings.Save` casts `$2::jsonb` because lib/pq sends `[]byte` as bytea.
- `PUT /admin/settings` is all-or-nothing: one bad key fails the whole request, nothing partially saved.
- The raw-error contract test (`no_raw_error_contract_test.go`) is a same-line textual scan, not a full parse — keep `err.Error()` and the response line apart if either must appear near each other.
- `.superpowers/` is git-ignored scratch for the SDD ledger (task briefs, reports); nothing under it is part of the shipped repo.
